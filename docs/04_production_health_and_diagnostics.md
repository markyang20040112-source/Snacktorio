# Snacktorio 數位雙生閉環檢查機制與二元健康診斷手冊 (Production Health & Diagnostics)

本文件定義 Snacktorio 產線規劃系統之「數位雙生閉環檢查機制」、「純二元健康燈號判定」、「雙槽物質操縱機底料湊數規範」與「故障翻譯字典」。
所有未來開發者與 AI 代理人在進行產線自檢、食譜新增或演算法擴充時，必須嚴格遵守本手冊。

---

## 一、 數位雙生閉環檢查流程 (Two-Stage Verification)

```
[產線計算機 (理論推導)]
         ↓ (純投影轉換，無自主猜測)
[沙盒模擬器 (實體拓撲)]
         ↓
【第一關：靜態鏡像一致性審計 (Mirror Audit)】
  ├─ 機台數量精確相等 (N_calc == N_sandbox)
  ├─ 副產物折抵連線精確對齊 (donor -> in-base)
  ├─ 分流器整數比權重精確吻合
  └─ 流體均分守恆合法性檢驗 (總產出 / M == 目標需量)
         ↓
【第二關：動態物理快進體檢 (Headless Physics Audit)】
  ├─ 背景快進執行 60 週期 (無 UI 快速收斂)
  ├─ 自動廚師機稼動率 >= 99.9% (100.0% 滿載)
  ├─ 內部加工節點滿足設計需量 (零非預期欠壓、零停機)
  ├─ 自癒補丁機台徹底清零 (HealNodes == 0)
  └─ 時序發酵緩衝槽零意外變質
```

## 二、 純二元健康狀態判定 (Binary Status)

本系統全面淘汰「黃燈（產能冗餘）」，避免因機台離散整數特性引發無意義的告警疲勞，回歸純粹客觀的二元判定：

| 狀態燈號 | 狀態名稱 | 判定條件 (物理不變量) | 使用者與前端呈現 |
|:---:|:---:|---|---|
| 🟢 | **健全 (Healthy)** | • 自動廚師機 100.0% 滿載運轉<br>• 全線無斷流、無死鎖<br>• 自癒機台 $\text{HealNodes} = 0$ | 綠色徽章，顯示「100% 滿載」，產線運轉完美。 |
| 🔴 | **故障 (Faulty)** | • 自動廚師機 $< 99.9\%$（欠壓或斷流）<br>• 存在 0% 停機設備（如祖源死鎖）<br>• 產生了自癒補丁機台（代表推導破防） | 紅色跳動警報。點擊展開【產線體檢診斷卡】。 |

## 三、 物質操縱機（重構機）雙槽拼湊折抵物理準則

依據遊戲原生 UI 結構，物質操縱機擁有 **2 個待消化物品欄** 與 **6 格緩衝庫存欄**，其運作遵循以下物理約束：

1. **總需量守恆定律**：
   - 物質操縱機轉化週期固定為 5 秒消耗 1 個任意物品，整台機台的額定底料需量恆為 **$0.20\text{/s}$**。
   - 兩個待消化槽位為**「共享庫存池 (Shared Inflow Pool)」**：
     $$\text{槽 A 流率 } (r_1) + \text{槽 B 流率 } (r_2) = 0.20\text{/s}$$
2. **入料端口上限**：
   - 每台物質操縱機最多接收 **2 種不同的底料來源**（對應 2 個待消化槽，嚴禁 3 種以上混接）。
   - 沙盒實體端口定義為 `in-base-1` 與 `in-base-2`，各自的 `rateRequired` 必須動態校準為其設計入料流率（例如 $0.10$ 與 $0.10$），嚴禁雙端口皆填 $0.20$ 以免引發二次欠壓懲罰。
3. **配對優先級**：
   - **第一優先（單源整台直供）**：單一工序過剩 $\ge 0.20\text{/s}$ 者優先 1:1 直供單台操縱機（佔用槽 A，槽 B 空載）。
   - **第二優先（雙源拼湊折抵）**：碎屑產能相互配對，滿足 $r_A + r_B \ge 0.20\text{/s}$ 直供單台操縱機之雙槽。
4. **祖源死鎖防護**：
   - 參與湊數之機台 A 與機台 B，其原料鏈均不得逆向依賴該目標操縱機之產物。

## 四、 故障代碼與診斷字典 (Diagnostic Dictionary)

當第二關檢驗失敗（亮 🔴 紅燈）時，診斷引擎依據物理卡點自動映射根本病因：

| 物理症狀 | 診斷代碼 | 疑似計算機根本病因 | 檢查與修復方向 |
|---|---|---|---|
| 物質操縱機 0% 停機 | `ERR_PROGENITOR_DEADLOCK` | 祖源閉環死鎖，候選 Donor 依賴自身產物。 | 檢查 `itemTraits.ts` 的 `isUpstreamAncestor` 或動態有向圖閉環 |
| 廚師機固定 50% 欠壓 | `ERR_FLUID_STARVATION` | 流體混管稀釋，或未落實 1:1 專線直供 / 均分。 | 檢查流體分配與 `dishBlueprintGenerator.ts` 專線邏輯 |
| 中間設備 80% 降載 | `ERR_RATE_PENALTY` | 輸入端 `rateRequired` 誤寫為額定值，造成二次扣減懲罰。 | 校準輸入端口之 `rateRequired` 為實際設計流率 |
| 相同設備負載不均 | `ERR_PARTITION_IMBALANCE` | 裝箱分流（Best-Fit）分配不均，下游目標全擠到同一台。 | 檢查目標分流分配器（`partitionTargetsToSuppliers`） |
| 輸送帶週期性停擺 | `ERR_CROSS_DONATION_CYCLE` | 多重構機 cross-donation 引發長震盪互鎖循環。 | 檢查有向圖可達性檢查與遞移閉包 (`canAddDependency`) |
